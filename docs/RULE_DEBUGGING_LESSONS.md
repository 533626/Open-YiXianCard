# 结算链取证与修复教训（2026-08-09）

> 来源：HF 最新语料 + 当前 Steam 客户端（build 24610558）采集的 mismatch 收口。
> 12 个 raw mismatch → 8 个 server-client drift + 2 个真实引擎差距 → 引擎差距清零。
> 每条教训都是实踩后写下的；完整锚点收据在私有 `research/original-game/DIAG_*` 与
> `battle-evaluator/generated/mirror-diagnosis/`，本文只写可复用的判定方法。

## 1. 反编译文本顺序 ≠ 执行顺序

- **现象**：async 状态机反编译的文本布局与执行顺序经常相反。杯弓蛇影反编译文本里
  扣血调用行排在施加内伤调用行之前，看似「先触发后施加」；按 IL 偏移顺序实际是
  「先施加内伤，再按当前层数触发一次」。
- **教训**：顺序判定以 IL offset 和真实回放为准，不以反编译文本行序为准。修共享扣血链前，
  先确认同一张卡内各调用的先后，再决定契约。

## 2. 开局效果的参数来源是运行时牌组，不是 fixture 原卡

- **现象**：开局效果分发按牌组格位**当前**卡牌结算，再按该卡 `otherParams` 生效
  （BattleCharacter.cs:11047-11124）；先手方厄劫缠身开局会把后手同格牌
  降级（如万事如意 11010013 → 11000013），后手开局效果因此按降级后参数结算（辟邪 2 → 1）。
- **教训**：带降级/置换/变形等开局副作用的场景，参数必须从牌组格位当前卡读取；静态按
  fixture 原卡参数实现，会在「先手降级 + 后手开局」这类组合下错一层。判据：先手完整开局
  （含副作用）先于后手开局，原版按 actor 分界顺序执行。

## 3. 临时升阶统一走 noUpgrade 门禁

- **现象**：画龙点睛等临时升阶路径曾直接 `id + 10000`；澄心剑胚 (19) 明确
  `noUpgrade=true` 而 10019 档位存在，导致错误升阶、终局生命偏差。
- **教训**：存在 `+10000` 档位 ≠ 可升阶。所有临时升阶路径（画龙点睛 / 狂剑升阶 /
  相生相成粽子）必须过 `can_upgrade_original_battle_deck_card`（含 `noUpgrade` 检查），
  与既有升阶路径共用同一门禁。

## 4. 服务器记录 ≠ 当前客户端：drift 判定标准

- **现象**：HF mirror 批次里约 0.1% 的 raw mismatch，用当前客户端 full-state 复跑后与
  Rust 逐 checkpoint exact，仅 HF expected 不同（winner 翻转或 hpDelta 偏差，如
  内伤层数、升阶档位、天赋候选顺序的差异）。
- **教训**：
  - 裁决权威是**当前客户端实测**，不是服务器记录，也不是反编译静态语义；
  - drift 不改引擎、不改 fixture expected（改了就偏离官方客户端）；
  - 分类不降低 raw 计数，raw 只在重新 screen 后下降——「总有 mismatch」的印象一半来自
    这个计数口径；
  - 处置：留机器可读收据（DIAG + mirror-diagnosis），后续从 first-party server 记录
    重新摄取该子集。

## 5. 共享扣血/负面状态链的差异常在调用方式，不在共享链本身

- **现象**：寒冰咒两次扣血调用各消耗一层护体（给共享链设「无视护体」是错的）；
  内伤「施加 + 立即触发」按 IL 顺序各走共享链；辟邪按实际生效层数抵扣负面状态。
- **教训**：共享扣血/负面状态链本身正确时，mismatch 常来自调用参数（护体开关、
  层数来源、是否走同一入口）。先核对调用点与参数，再决定改共享链还是改调用方式。

## 6. 改共享结算链必须同步旧契约测试并跑全量

- **现象**：五行天髓改为逐次消耗后，旧契约测试的敏捷期望仍编码「不消耗」的旧语义，
  定向测试全绿、全量 `cargo test --lib` 回归失败。
- **教训**：共享结算链语义变更后跑全量 lib 测试；契约测试若编码了旧语义必须同步更新，
  并注明证据锚点（反编译行号/回放 case），避免把旧 bug 语义固化进测试。

## 每项修复的验证闭环

1. 首差定位：`replay-focus` / `dump-aligned-rust-full-state.ts`（需客户端采集，串行）；
2. 全量回归：`cargo test --lib`（共享链变更必跑）、`bun run check:rust:contracts`；
3. 基线确认：`replay_slice --admission <外部批次目录>` 全量 strict，
   `winner` / `actorTurn` / `hpDelta` 三字段同时匹配，不放宽。
